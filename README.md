# dependency-graph-cli

Консольный инструмент визуализации графа зависимостей Maven-пакетов
(практическая работа по конфигурационному управлению, вариант 7).

Готовые менеджеры пакетов и библиотеки для получения зависимостей не используются.

## Этапы

- [x] Этап 1. Минимальный прототип с конфигурацией (YAML)
- [ ] Этап 2. Сбор данных о прямых зависимостях из Maven-репозитория
- [ ] Этап 3. Построение графа (DFS без рекурсии, глубина, фильтр, циклы, тестовый режим)
- [ ] Этап 4. Обратные зависимости
- [ ] Этап 5. Визуализация (D2, PNG, ASCII-дерево)

## Требования

- Java 21
- Maven 3.9+

## Сборка и запуск

```bash
./run.sh                          # использует config.yaml из корня проекта
./run.sh tests/configs/valid.yaml # другой файл конфигурации
```

Или вручную:

```bash
mvn package
java -jar target/dependency-graph-cli-1.0-SNAPSHOT.jar [путь к config.yaml]
```

## Конфигурация

Все параметры задаются в YAML-файле (по умолчанию `config.yaml`):

| Параметр      | Тип     | Описание                                                                 |
|---------------|---------|--------------------------------------------------------------------------|
| `packageName` | строка  | Пакет `groupId:artifactId:version`; в тестовом режиме — заглавные буквы (`A`) |
| `repository`  | строка  | URL Maven-репозитория (http/https); в тестовом режиме — путь к файлу графа |
| `outputFile`  | строка  | Имя PNG-файла с изображением графа, должно заканчиваться на `.png`      |
| `filter`      | строка  | Пакеты, в имени которых есть эта подстрока, пропускаются; необязательный |
| `testMode`    | boolean | `true` — читать граф из тестового файла вместо репозитория               |
| `asciiTree`   | boolean | `true` — вывести зависимости в виде ASCII-дерева                         |
| `maxDepth`    | целое   | Максимальная глубина анализа, не меньше 1                                |

Пример:

```yaml
packageName: com.google.guava:guava:33.0.0-jre
repository: https://repo1.maven.org/maven2
outputFile: graph.png
filter: test
testMode: false
asciiTree: true
maxDepth: 3
```

## Обработка ошибок

При любой ошибке программа выводит одну понятную строку и завершается с кодом 1.
Проверяются:

- файл конфигурации не найден, пустой, повреждён или содержит не пары ключ-значение;
- повторяющиеся и неизвестные ключи (например, опечатка `maxDeph`);
- отсутствие любого обязательного параметра;
- неверный тип значения (строка, true/false, целое число);
- недопустимые значения: формат имени пакета, URL или существующий файл
  в зависимости от режима, расширение `.png`, глубина меньше 1.

## Тесты

В `tests/configs` лежат конфигурации для каждого случая (корректные и с ошибками).
Скрипт прогоняет приложение на всех и проверяет код возврата и сообщение:

```bash
mvn package
./tests/run_config_tests.sh
```

## Структура

```
src/main/java/org/example/
├── Main.java                  точка входа
└── config/
    ├── Config.java            настройки приложения
    ├── ConfigLoader.java      чтение YAML и проверка наличия и типов параметров
    ├── ConfigValidator.java   проверка значений параметров
    └── ConfigException.java   ошибка конфигурации
tests/
├── configs/                   тестовые конфигурации
├── graphs/                    файлы тестовых графов
└── run_config_tests.sh        прогон тестов конфигурации
```
