# dependency-graph-cli

Консольный инструмент визуализации графа зависимостей Maven-пакетов
(практическая работа по конфигурационному управлению, вариант 7).

Готовые менеджеры пакетов и библиотеки для получения зависимостей не используются.

## Этапы

- [x] Этап 1. Минимальный прототип с конфигурацией (YAML)
- [x] Этап 2. Сбор данных о прямых зависимостях из Maven-репозитория
- [x] Этап 3. Построение графа (DFS без рекурсии, глубина, фильтр, циклы, тестовый режим)
- [x] Этап 4. Обратные зависимости
- [ ] Этап 5. Визуализация (D2, PNG, ASCII-дерево)

## Требования

- Java 21
- Maven 3.9+

## Сборка и запуск

```bash
./run.sh                          # использует config.yaml из корня проекта
./run.sh my-config.yaml           # другой файл конфигурации
./run.sh --reverse my-config.yaml # обратные зависимости (только в тестовом режиме)
```

Или вручную:

```bash
mvn package
java -jar target/dependency-graph-cli-1.0-SNAPSHOT.jar [--reverse] [путь к config.yaml]
```

## Конфигурация

Все параметры задаются в YAML-файле (по умолчанию `config.yaml`):

| Параметр      | Тип     | Описание                                                                 |
|---------------|---------|--------------------------------------------------------------------------|
| `packageName` | строка  | Пакет `groupId:artifactId:version`; в тестовом режиме — заглавные буквы (`A`) |
| `repository`  | строка  | URL Maven-репозитория (http/https); в тестовом режиме — путь к файлу графа |
| `outputFile`  | строка  | Имя PNG-файла с изображением графа, должно заканчиваться на `.png`      |
| `filter`      | строка  | Пакеты, в имени которых есть эта подстрока, пропускаются; необязательный |
| `testMode`    | boolean | `true` — читать граф из тестового файла вместо репозитория               |
| `asciiTree`   | boolean | `true` — вывести зависимости в виде ASCII-дерева                         |
| `maxDepth`    | целое   | Максимальная глубина анализа, не меньше 1                                |

Пример:

```yaml
packageName: com.google.guava:guava:33.0.0-jre
repository: https://repo1.maven.org/maven2
outputFile: graph.png
filter: test
testMode: false
asciiTree: true
maxDepth: 3
```

## Получение зависимостей (этап 2)

Программа сама строит путь к POM-файлу пакета в репозитории, скачивает его
стандартным `java.net.http.HttpClient` и разбирает XML стандартным DOM-парсером.

Что учитывается:

- родительские POM (`parent`): наследуются переменные, зависимости
  и `dependencyManagement`;
- переменные `${...}` из `properties`, а также `${project.groupId}`,
  `${project.version}` и `${project.parent.*}`;
- версии и области действия из `dependencyManagement`, включая импорт BOM
  (`<scope>import</scope>`);
- в результат попадают только зависимости с областью `compile` и `runtime`;
  `test`, `provided`, `system` и необязательные (`optional`) пропускаются;
- зависимости внутри плагинов (`build/plugins`) не учитываются.

Упрощения по сравнению с настоящим Maven:

- профили (`profiles`) не учитываются;
- диапазоны версий (`[1.0,2.0)`) не разрешаются и выводятся как есть;
- `classifier` и `type` при сопоставлении с `dependencyManagement` не учитываются;
- исключения (`exclusions`) пока не применяются.

## Граф зависимостей (этап 3)

Граф строится обходом в глубину (DFS) без рекурсии: вместо рекурсивных вызовов
используется явный стек, в котором лежит путь от корня к текущему пакету.

- **Максимальная глубина.** Корень имеет глубину 0, его прямые зависимости — 1.
  Пакеты на глубине `maxDepth` попадают в граф, но их зависимости не загружаются
  (в выводе: `not expanded: max depth reached`). Если пакет сначала встретился
  глубоко, а потом ближе к корню, он раскрывается повторно.
- **Фильтр.** Пакеты, имя которых содержит подстроку `filter`, не попадают в граф
  и не раскрываются (в выводе: `Skipped by filter`). До их зависимостей можно
  дойти другими путями.
- **Циклы.** Если зависимость уже лежит в стеке, найден цикл: он выводится
  в разделе `Cycles`, а обход дальше по нему не идёт. Каждый пакет обходится
  один раз, поэтому программа не зацикливается.
- **Недоступные пакеты.** Если POM-файл одной из транзитивных зависимостей
  не удалось получить, она остаётся в графе без зависимостей, а причина
  выводится в разделе `Warnings`.

Пример вывода:

```
Dependency graph of A:
  A -> B
  B -> C
  C -> A, D
  D -> D
Cycles:
  A -> B -> C -> A
  D -> D
Warnings: none
Packages: 4, dependencies: 5
```

### Тестовый режим

При `testMode: true` граф читается не из Maven, а из текстового файла
(путь указывается в `repository`). Пакеты называются заглавными латинскими
буквами, каждая строка описывает один пакет и его прямые зависимости:

```
A: B C
B: D
C: D
D:
```

Пакет, для которого нет своей строки, считается пакетом без зависимостей.
Анализируемый пакет (`packageName`) должен быть описан в файле.

## Обратные зависимости (этап 4)

С флагом `--reverse` программа выводит пакеты, которые зависят от заданного
(прямо или через другие пакеты). Режим работает с тестовым репозиторием
(`testMode: true`): для настоящего Maven-репозитория узнать, кто зависит
от пакета, без полного индекса репозитория нельзя.

Используется тот же обход в глубину, что и на этапе 3, но по перевёрнутому
репозиторию: в нём зависимостями пакета считаются пакеты, которые от него
зависят. Поэтому так же работают максимальная глубина, фильтр и поиск циклов.

Режим включается флагом, а не параметром конфигурации: это способ запуска,
а не одна из семи настроек, перечисленных в задании.

```
$ ./run.sh --reverse tests/graph-configs/reverse-diamond.yaml
Packages that depend on D:
  B, A, C
Reverse dependency paths:
  D <- B, C
  B <- A
  A <- (no dependents)
  C <- A
Cycles: none
Warnings: none
Packages depending on D: 3
```

Стрелка `X <- Y` означает, что пакет `Y` зависит от пакета `X`.

## Обработка ошибок

При любой ошибке программа выводит одну понятную строку и завершается с кодом 1.
Проверяются:

- файл конфигурации не найден, пустой, повреждён или содержит не пары ключ-значение;
- повторяющиеся и неизвестные ключи (например, опечатка `maxDeph`);
- отсутствие любого обязательного параметра;
- неверный тип значения (строка, true/false, целое число);
- недопустимые значения: формат имени пакета, URL или существующий файл
  в зависимости от режима, расширение `.png`, глубина меньше 1;
- репозиторий недоступен, пакет не найден (HTTP 404), POM-файл повреждён
  или версию зависимости определить невозможно;
- файл тестового репозитория имеет неверный формат (с номером строки)
  или не содержит анализируемого пакета;
- неизвестный аргумент командной строки или режим `--reverse` без тестового режима.

## Тесты

В `tests/configs` лежат конфигурации для каждого случая (корректные и с ошибками).
Корректные указывают на недоступный адрес `127.0.0.1:9`: так проверяется, что
конфигурация прошла все проверки и программа перешла к запросу в репозиторий.
Скрипт прогоняет приложение на всех и проверяет код возврата и сообщение:

```bash
mvn package
./tests/run_config_tests.sh
```

В `tests/graphs` лежат тестовые репозитории, а в `tests/graph-configs` — конфигурации
для демонстрации этапа 3 на разных случаях:

| Конфигурация             | Граф            | Что показывает                                      |
|--------------------------|-----------------|-----------------------------------------------------|
| `diamond.yaml`           | `diamond.txt`   | общая зависимость D обходится один раз              |
| `cycle.yaml`             | `cycle.txt`     | цикл A -> B -> C -> A и петля D -> D                |
| `depth-limit.yaml`       | `chain.txt`     | ограничение глубины (`maxDepth: 2`)                 |
| `filter.yaml`            | `diamond.txt`   | пакет C пропущен фильтром                           |
| `shortcut.yaml`          | `shortcut.txt`  | пакет E сначала встречен глубоко, потом ближе к корню |
| `undefined-package.yaml` | `undefined.txt` | пакет без своей строки считается листом             |
| `invalid-file.yaml`      | `invalid.txt`   | ошибка формата файла с номером строки               |
| `missing-root.yaml`      | `diamond.txt`   | анализируемого пакета нет в файле                   |

Конфигурации для этапа 4 запускаются с флагом `--reverse`:

| Конфигурация               | Граф            | Что показывает                                    |
|----------------------------|-----------------|---------------------------------------------------|
| `reverse-diamond.yaml`     | `diamond.txt`   | от D зависят B, C и (через них) A                 |
| `reverse-cycle.yaml`       | `cycle.txt`     | обратные зависимости внутри цикла                 |
| `reverse-depth-limit.yaml` | `chain.txt`     | ограничение глубины (`maxDepth: 2`)               |
| `reverse-filter.yaml`      | `diamond.txt`   | пакет B пропущен фильтром, A найден через C       |
| `reverse-undefined.yaml`   | `undefined.txt` | пакет без своей строки тоже можно анализировать   |
| `reverse-root.yaml`        | `diamond.txt`   | от корневого пакета A никто не зависит            |

```bash
./tests/run_graph_tests.sh
```

